# 22. SFAC 成功—失败双向区域信用预注册

## 0. 研究问题

冻结主算法 `SGWO.m`、`main` 和已有正式结果保持不变。G2-TR、G2-AFE 和 PCSS 不再继续：

- G2-TR：相对 G1+E 没有净收益；
- G2-AFE：方向信息有弱信号，但相对 G1+E 仍无净收益；
- PCSS：P0 运行时间为 V1 的 3.06 倍，超过预注册的 1.15 倍上限，门控 240 次检查只打开 10 次。

本分支只检验一个轻量机制：

> 在已经验证有效的多区域精英档案中，把“历史成功信用”改为“成功加分、失败扣分、信用下限为 0”的双向区域信用，能否在保持随机探索和档案多样性的同时，提高真实评价预算的利用效率？

机制名称：SFAC — Success–Failure Adaptive Credit。

## 1. 只改一条核心规则

当前档案中心信用 `C_j` 的现有规则是：

- 候选改善种群，或触发档案插入/替换：`C_j ← C_j + 1`；
- 候选失败：`C_j` 不变；
- 单中心候选的中心选择权重：`P(c_j) ∝ 1 + C_j`。

SFAC 只把第二部分改为：

- 真实成功：`C_j ← C_j + 1`；
- 真实失败：`C_j ← max(0, C_j - 1)`；
- 权重仍然为 `P(c_j) ∝ 1 + C_j`，因此任何中心都不会永久失去被选择的机会。

固定参数，不扫描：

- 成功增量 `+1`；
- 失败减量 `-1`；
- 信用下限 `0`；
- 信用上限不设置；
- 选择权重仍为 `1 + C_j`。

## 2. 中心身份与线段候选

- 每个真实档案中心分配一个唯一 `ArcID`。
- 单中心候选记录生成时的父中心 ID。
- 双中心线段候选同时记录两个父中心 ID。
- 候选被真实评价后：
  - 如果成功，两个父中心各 `+1`；
  - 如果失败，两个父中心各 `−1`，但不能低于 0。
- 档案中心被替换时：
  - 新中心分配新 ID；
  - SFAC 开启时新中心信用从 0 开始；
  - 旧中心的候选反馈在新中心上无效，不能把反馈记到错误位置。
- 如果评价时父中心已经被替换或移除，该反馈记为 stale feedback，不更新任何当前中心。

## 3. 不改变的部分

- G1、G2、E 的候选生成公式；
- 单中心/双中心候选数量比例；
- 档案空间分离规则 `dSepFrac=0.02`；
- 候选池 `M=100`；
- 每轮真实评价 `K=10`；
- 初始化池、接受规则、边界处理和真实 FE 计费；
- 所有正式基线和现有结果。

SFAC 不增加新的候选生成算子，不引入代理模型、RL、GNN 或新的超参数。

## 4. 过程记录

每个运行必须记录：

- `ArcCredSum`、`ArcCredMax`、`ArcCredNonzero`、`ArcCredZeroFrac`；
- `ArcGenCountTotal`、`ArcGenTopShare`、`ArcGenEntropy`；
- `ArcEvalCountTotal`、`ArcEvalTopShare`、`ArcEvalEntropy`；
- `ArcEvalSuccessRate`；
- `ArcStaleFeedback`；
- `ArcReplacementCount`；
- 最终误差、停滞恢复、探索效率与运行时间。

这些指标用于判断机制是否真的改变了区域利用行为，但不能替代最终性能门槛。

## 5. P1 开发实验

### 5.1 协议

- CEC2017，D=50。
- 函数：F7、F10、F13、F14、F16、F18、F22、F24。
  - 覆盖简单多峰、混合和组合函数；不在 G2-TR 和 G2-AFE P1 的函数集合中。
- 种子：3121–3130；运行前已扫描现有 CSV，未发现使用。
- 真实 FE：30,000。
- 种群：N=50，K=10，nG2=12，nE=38，`screenPolicy='random'`。
- 并行：MATLAB local 恰好 4 worker，禁止串行降级。
- 输出：`sparse_q/results/sfac_p1_<timestamp>/`，失败运行保留。

### 5.2 实验臂

P1 先跑两个主要版本：

| 臂 | 入口 | 信用规则 |
|---|---|---|
| V1-Frozen | `SGWO` | 成功 +1，失败不扣 |
| V1-SFAC | `SGWO_SFAC`，`sfacOn=1` | 成功 +1，失败 −1，下限 0 |

如果 V1-SFAC 通过 P1 门槛，再运行可选的第三臂：

| 可选臂 | 入口 | 信用规则 |
|---|---|---|
| V1-Uniform | `SGWO_SFAC`，`sfacOn=1`，`sfacUniform=1` | 不使用权重的均匀中心选择，用于判断信用反馈本身的作用 |

Uniform 臂必须在 P1 结果之外单独预注册或作为本文件的条件阶段运行，不能根据 P1 结果临时改变统计口径。

### 5.3 规模

2 臂 × 8 函数 × 10 种子 = **160 次独立运行**。

冒烟：F7、seed 3993、3,000 FE，不进入统计。

## 6. P1 晋级门槛

### H1：SFAC 相对冻结 V1 有净收益

1. 跨函数中位最终误差比 ≤0.98；
2. 至少 6/8 个函数获胜；
3. 没有函数中位误差比 >1.20；
4. SFAC 平均运行时间 ≤ V1 的 1.15 倍；
5. 报告逐函数配对 Wilcoxon 和 Holm 校正，但显著性不能替代上述门槛。

### H2：机制行为证据

必须报告：

- SFAC 是否确实产生信用下降事件；
- `ArcCredZeroFrac`、`ArcGenTopShare`、`ArcEvalTopShare` 与 V1 的差异；
- 分阶段区域成功率是否发生预期变化；
- 不能只展示最终最优值。

### H3：不破坏冻结算法

- `sfacOn=0` 时，`SGWO_SFAC` 必须与冻结 `SGWO.m` 逐位一致，包括 Trace、Best 和 FE 计数。
- 档案 ID 和过程计数器不得消耗候选生成随机流。
- 真实 FE 预算严格一致。

## 7. 淘汰规则

- H1 不通过：停止 SFAC，不扫描信用增量、失败减量、下限或权重函数。
- H1 通过、H2 没有机制证据：只能作为性能增强，不能声称区域信用自校正有效。
- H1、H2、H3 全部通过：才进入 29 函数、D=50、100k FE、30 个全新种子的正式确认。
- 如果 SFAC 成为主算法，必须重新确认 D=100、UAV 应用和所有受影响的正式对比。
- 不使用 P1 的 3121–3130 作为最终测试种子。

## 8. 预注册时间

本文件在实现和 P1 前冻结。实现只允许增加信用更新规则和过程记录；任何额外机制都必须另立预注册。

## 9. P1 前运行时间口径附录（仅测量修正）

冻结 `SGWO.m` 与消融脚手架 `SGWO_ABLATION.m` 在相同状态下 Trace/Best 逐位一致，但脚手架实现本身约慢 1.7 倍。因此：

- 机制运行时间的正式对照使用 **A3-Scaffold**（`SGWO_ABLATION` base state）；
- SFAC 运行时间门槛改为：`SFAC / A3-Scaffold ≤ 1.15`；
- 同时报告 `SFAC / V1-Frozen`，但该比值包含脚手架解释器开销，不作为机制开销判定；
- P0 实测：`SFAC/A3-Scaffold=1.062`，`A3-Scaffold/V1=1.720`。

该附录只修正运行时间的实现对照，不改变候选池、FE、信用规则、函数、种子或最终误差门槛。
