# 附：实现层面的运行时间修正（不影响机制定义）

日期：2026-10-22（P1 正式批次启动前）

## 1. 第一版实现的运行时间缺陷

第一次启动 P1（20:06，结果目录 `sparse_q/results/aborted_sals_p1_draft_20261022_200633`）后，
同批计时显示活跃臂 **21–23 s**、冻结臂 **5.7 s（3.7×）**。逐段剖析（见
`reports/sals_runtime_optimization.md`）确认原因是活跃/审计块内部的两个 6*D=300 次循环：

1. 分层结构的层内抖动按维度逐列抽取 `rand(sSals,nS,1)`（每宏代 300 次 RandStream 调用）；
2. 分层实现率诊断按维度逐列调用 `unique()`（每宏代 300 次）。

一个宏代 9,995 次 → 每次运行约 600 万次微调用。**这与机制定义无关，纯属实现方式。**

## 2. 修正方式：逐位等价的运行时间优化

- 抖动改为一次 `rand(sSals,nS,mS)`（列主序填充，取值序列与 300 次标量调用完全相同）；
- 分层实现率改为向量化 `sort/floor/diff` 判定（不消耗随机数，计数结果相同）；
- 位置重建改为 `salsRebuildPos` 一次性向量化（逐元素算术与逐候选循环一致，其中 `norm()`
  仍逐候选调用以保持与优化前完全相同的浮点结果）；
- STEER 触发/方向仍按优化前 **B1,C1,B2,C2,…** 的交错顺序逐候选抽取；
- 几何诊断（分层实现率/离散度/位移）只在 `audit` 模式记录，活跃臂不再支付该开销。

**逐位等价性证据**（均在启动前完成）：

- `tests/test_sals_opt_equivalence.m`：3 个单元 × 4 个模式（none/audit/iid/lhs）与
  `tests/ref/SGWO_SALS_preopt.m`（优化前实现）**逐位一致**；Trace/Best/FE/计数器/审计诊断全部相同。
- `tests/test_sals_rebuild_equivalence.m`：1500 个候选的向量化重建与逐候选循环实现**逐元素一致**。
- `tests/test_sals_contract.m`：`none`/`audit` 与冻结骨架逐位一致；audit 分层实现率 = 1.000；
  `iid`/`lhs` 真实 FE 精确。

因此 `docs/67` 的 P0 结论（40 次被动审计 8/8 通过）对最终实现仍然成立：audit 模式的轨迹与全部
几何诊断均逐位不变，无需重跑。
