# 54. LLT 排名门控版（rank）功效充分的开发验证预注册

日期：2026-10-22
状态：dev 阶段（种子 3359–3368，15 函数 × 10 种子）；确认阶段另行冻结。

## 0. 为什么要重做 dev

第一次 dev（`53_LLT_ANCHOR_DEV.md`，8 函数 × 5 种子，种子 3354–3358）判定 anchor 版本不晋级（m=1.103，c=1.215）。
但该批次**功效不足**，不能作为机制判断依据：同一个 ring 机制在 15 函数 × 10 种子的 P1 批次上
m=0.794，在这个 8×5 的 dev 批上 m=1.055（F1 从 1.026 变 0.558、F14 从 0.565 变 1.912），
即 5 种子的"逐函数中位比"统计量方差极大。因此需要一次与决策规模匹配的开发验证。

同时，LLT-P1 的逐函数诊断给出了明确的失败机制：

| 现象 | 证据 |
|---|---|
| 退化集中在需要强收敛压力的函数 | F3：B/A 1.598、C/A 1.599，10/10 种子变差；F30：B/A 1.354、C/A 1.451 |
| 收益集中在多峰/混合函数 | F7 0.540、F14 0.565、F20 0.725、F16 0.738、F18 0.745、F13 0.783、F10 0.785 |
| 收敛阶段分解（同一批数据） | F3 比值随 FE 单调恶化（1.12→1.63），F1/F30 的伤害从 10% FE 就存在 |
| 与匹配对照相比 | B/C 中位 0.976，仅 9/15 胜 → "局部质量"本身只贡献很小一部分 |

结论：**把全部 50 只狼的领导都局部化**会丢掉全局收敛压力。

## 1. 排名门控设计（rank）

- 每代按**真实评价适应度**给 50 只狼排名；
- 排名**前半**（较好）：仍使用全局 (alpha, beta, delta) —— 保留收敛压力；
- 排名**后半**（较差）：使用固定环形窗口（w=7）内真实评价最优的 3 只狼作为自己的领导 —— 提供探索与池内多样性；
- 匹配对照 `rankrand`：同样只对后半使用局部窗口，但窗口内的 3 个领导**随机**抽取（同一批随机数消耗）；
- 环窗口 = 7、领导数 = 3、门控比例 = 50% 全部固定，不扫描；
- 聚合公式、A/C 结构、候选池 M=100、筛选、E、档案、接受规则、FE 计费全部不变。

与老师 RL_GNN_PSO 的关系：他那里是"停滞 + 排名后半 → 重启粒子"；这里是"排名后半 → 使用局部领导"，
同样简单、可消融，但作用在候选生成而不是破坏个体历史。

## 2. dev 协议

- 15 个函数：F1、F3、F4、F7、F10、F11、F13、F14、F16、F18、F20、F22、F24、F26、F30；
- 种子：3359–3368（10 个全新种子，运行前扫描确认未使用）；
- 臂：A=冻结、B=ring（参考）、C=rank（候选）、Crand=rankrand（匹配对照）；
- 4 臂 × 15 函数 × 10 种子 = 600 次运行，D=50，100k FE。

## 3. 预注册选择规则

设 `m = median_F(median_seed(err_rank/err_A))`，`w = #(F: median_seed ratio < 1)`，`c = max_F(...)`。

- **晋级确认**：`m ≤ 0.95` 且 `w ≥ 11/15` 且 `c ≤ 1.20`；
- 附加检查（不满足则确认阶段必须保留对照臂并限制主张）：rank 相对 rankrand 的中位比 ≤1.00 且胜 ≥9/15；
- **不晋级**：不满足 → 停止 LLT 方向（含 ring/anchor/rank 全部变体），
  不扫描窗口大小、门控比例、排名阈值或拓扑形式。
