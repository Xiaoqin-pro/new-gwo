# 57. RED 预注册：冗余评价剔除（与 E 正交的稀疏筛选机制）

日期：2026-10-22
状态：dev 批次运行前冻结（种子 3369–3378）。

## 0. 机制一句话

**在每代 K=10 个真实评价名额的抽取阶段，拒绝与"本代已接受候选"距离小于 ε·span 的候选**
（有界重抽，上限 5 次）——只改"谁被评价"，不改候选池、领导、档案、接受规则与 FE 计费。

- `redMode='none'`：与冻结 `SGWO_ABLATION` 逐位一致（合约测试）；
- `redMode='audit'`：冻结筛选 + 被动记录（行为不变，逐位一致）；
- `redMode='drop'`：RED 筛选，`redEps` 取 0.02（主）或 0.005（剂型对照）。

## 1. 前提（已在本仓库测到，需在全尺度复核）

LLT-P0（种子 3337–3341，D=50/100k）测得：每代被选中的 10 个候选中，有 **20.0%–31.5%** 与其他被选候选
距离 <2% 跨度（8/8 函数）。D=30 冒烟运行还显示近邻重复候选的**价值更低**：
改进父代/参考的比例 0.416 vs 0.533，进入档案的比例 **0.001 vs 0.185**。

dev 批次的 audit 臂将把这两条前提在 D=50/100k 全尺度上重新测量（逐函数）。

## 2. 与 E 的正交性

RED 只作用于"筛选层"：不读取档案、不改变 E 的候选生成/准入/删除规则，也不改变 G1 公式。
E 开/关两种构型下 RED 都可运行（确认阶段将包含 E 关臂），因此可以独立消融。

## 4. 预注册门槛

- **H1（主）** B/A：函数级中位误差比 ≤0.98；≥11/15 个函数获胜；无函数 >1.20；运行时间比 ≤1.15；
- **过程证据（报告，不作门槛）**：
  1. 前提：audit 臂中 `RedDupImpRate < RedDistImpRate` 且 `RedDupArcRate < RedDistArcRate` 的函数比例；
  2. 有效性：`RedSelDupRate(B)` 明显低于 `RedSelDupRate(A)`（规则确实降低了重复率）；
  3. 剂量：若 `B ≤ C ≤ A`（越强的去重越好），支持"冗余"解释；若 B 与 C 无差异，则不能声称去重幅度有价值。
- **不通过** → 停止 RED，不扫描 ε（除已注册的 0.005/0.02 两点）、不扫描重抽上限或评价顺序。
