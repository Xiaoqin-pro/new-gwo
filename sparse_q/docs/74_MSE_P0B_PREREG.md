# 74. MSE P0b：修正口径后的被动审计（新种子）

日期：2026-10-22　状态：**运行前冻结**

## 1. 为什么有 P0b（诚实记录）

`docs/72` 的 P0（批次 `mse_p0_20261022_231605`，8 函数 × 5 种子 3489–3493）结果：
- 门槛2 可区分性：**8/8 通过**（细/基准 = 0.50–0.52，粗/基准 = 1.78–1.99）；
- 门槛4 可到达：**8/8 通过**（每类约 10% 的候选被真实评价）；
- 门槛3 非退化：**1/8 通过** —— 粗类"任意一维触界"的比例为 49%–97%。

问题在于**门槛3 的操作化过严**：`any(y<=lb | y>=ub)` 在 D=50 下只要 1/50 维触界就计为"裁剪"，
而 `docs/72` 的原意是"避免粗尺度候选**整体退化为边界点**"。这与仓库中 PCSS 的
P0a（预注册口径）→ P0b（修正口径、全新种子）先例一致：口径修正必须另立预注册、换新种子，
不得回到同一批数据上重新解释。

## 2. P0b 设计（新种子 3504–3508，8 函数 × 5 种子 = 40 次，被动 audit）

同一 `mseMode='audit'`（与冻结终版逐位一致），新增记录：

1. `clip_frac`：每个候选被裁剪坐标占 D 的比例（**平均**，而非"是否有一维触界"）；
2. `surv`：`||y_clip − c|| / ||d_intended||`，即**预期位移的存活率**（1=完全没被裁掉）；
3. `disp_real_ratio`：裁剪后 粗类平均位移 / 基准类平均位移（设计目标 2.0；坍缩会显著低于 2）。

## 3. 门槛（运行前固定）

对同一函数同时满足以下三条记为该函数通过；**≥6/8 个函数通过** 才允许进入 P1：

1. 粗类 `clip_frac` ≤ **0.10**（平均触界坐标不超过 10%）；
2. 粗类 `surv` ≥ **0.85**（预期位移基本存活）；
3. `disp_real_ratio` ∈ **[1.7, 2.1]**（粗尺度确实更远，没有坍缩到边界同一点）。

**不通过 → 永久停止 MSE 线**（不再改口径、不改尺度集合、不改对照常数）。
