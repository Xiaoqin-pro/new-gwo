# 05 — Codex 通宵工作流（最多 8 小时 / 40 个配置）

## 阶段 0（约 20–40 分钟）：环境及基线审计
- 标定 MATLAB/4 workers；发现 CEC2017 源码、有效 baselines、旧成果；对强 GWO 做作者实现核查。
- 如果 4-worker 无法启动、CEC mex 不兼容或未找到可信基线，立即报告并停止正式实验。

## 阶段 1（约 30–60 分钟）：重写标准 GWO 与诊断
- 独立实现新工程的标准 GWO，跑Sphere/Rastrigin 等合成单元测试及官方 CEC 小预算正确性测试。
- 看 `docs/02`：找停滞严重且探索浪费明显的失败类型，提出 2 条量化的模块假设。
- 在 `experiments/registry.csv` 预先登记分组、参数及检验门槛。

## 阶段 2（主要时间）：最小改动循环
每轮四步：诊断 -> 写假设 -> 单模块小样本并行跑 -> 对强基线的同 FE 趋势、行为指标和 CPU 成本筛选。
- 配置数量硬上限 40；同一思路最多试少量预先登记的参数；无改进时转换假设而非无穷微调。
- 每轮 5 seeds 开发，部分通过再 10 seeds 复核；**不得用正式 30 seeds 的最终测试集继续调参**。
- 每批已完成的运行当场落盘。只调整新算法文件，不改任何 baselines。
- 坚持双轴：有效探索率/早期FE质量 + 停滞恢复率；最终同FE强基线表现为晋级必要条件。

## 阶段 3（剩余时间）：冻结验证
只对固定版本进行 29 函数×30 seeds、D=50 与条件允许时 D=100；只在 4 workers 能完成的资源范围内执行。**时间不足就报告未完成项，不允许自动缩减正式运行次数后冒称完成**。
运行所有已登记 strong baselines（可复用严格可比且已审计的历史数据，否则新运行）。生成数据表和曲线。

## 研发阶段建议晋级门槛（不是“SCI必过”的数值）
1. 无违反 FE/结果一致性、无基线适配缺陷、无测试泄漏。
2. 在独立开发验证上，对现有最强 GWO 与至少一个强 PSO/CSO 的 median error/AUC 有稳健改善趋势，且不只来自某一个函数（见消融报告）。
3. 有真实停滞恢复增益且有有用探索评价率增益；单纯新颖率/随机大跳提高不算。
4. 4-worker 运行不中断，单 run 的 CPU/墙钟负担没有与所得精度完全不成比例；若新方法明显更慢，明确 Pareto tradeoff。
5. 必须能写出 1–2 个与近年文献区分开来的机制贡献；不能只是名字新。

## 提前停止
出现连续 3 批没有足够稳健改进、达到 8 小时或 40 配置、异常多数、资源过载、4-worker 丢失、CEC 有版本错误 => 停止并诊断；不能一直补跑直到显著。
